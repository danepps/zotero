   `Integration.resetSessionStyles` promises and retains completed failures

   reproduction now waits for every session in 1/3/10/30/100-session runs.
2. **Style collision protection:** startup repair and Settings installs check
   title and visible/hidden destination-file collisions inside the command gate.
   They preserve other style identities and unindexed files and report actionable

   deletes no files.
3. **Structural metadata:** direct namespace-aware CSL metadata replaces regex
   matching. Comments, nested lookalikes, duplicates, foreign namespaces and
   malformed XML cannot supply the expected ID. Settings installation uses the
   same validated bytes and identity checks; the misleading-comment reproduction
   is rejected before installation.

## Remaining decisions and compatibility policy

- **Scope settled:** no journal engine, data-table transcription, licensing
  investigation, abbreviation provider hook, or associated CSL call-site edits
  for 2.0. The [render-time study](journal-abbreviation-render-time-feasibility.md)
  and [library-write study](journal-abbreviation-feasibility.md) remain deferred
  reference material; revisiting them requires a later scope decision, without
  a promised release number.
- **Style gates:** retain the current RTF-chain fail-open identity policy for
  this release. The new global et-al hook fails closed on unknown identity and
  is limited to built-ins; extra styles and `allStyles` do not widen it.
- **Compatibility:** style sync has no runtime compatibility-version gate.
  Before publishing a built-in CSL, require render fixtures with the latest
  stable plugin and the 2.0 candidate. Preserve the output contracts used by
  older installed plugins at the existing style IDs. Hold incompatible CSL
  publication until a transition is designed. This is a release-process gate,
  not a claim that timestamps establish compatibility.
- **Supported applications:** before manual testing, select and record exact
  Zotero, Word, LibreOffice, OS, and processor versions. Existing docs disagree
  about Zotero version labels; reconcile support claims with tested builds.
  Include HTML/text and Google Docs for et-al, while the RTF chain stays inactive
  there.
- **Documentation ownership:** update Codex/project docs when implementation
  changes their contracts. Claude-owned instructions remain read-only without
  specific authorization; supply required sister-document changes for Claude.
  Historical model/delegation decisions below do not prescribe this session's tools.
