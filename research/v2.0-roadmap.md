## Phase 0 — foundation (before any feature code)

From the Codex review (`2.0-plan-review.md`), findings verified against the plugin and
`zotero/zotero@main` on 2026-07-27:

1. **`build.sh` staged version injection** — today the version argument only names the
   file; the archived `manifest.json` keeps the working-tree version, defeating the
   fourth-component test-build convention. Stage, inject, verify with `unzip -p`, fail
   on mismatch. Lands before the first 2.0 test XPI.
2. **Wrapper hardening** — capture `_orig`/module refs at wrapper entry (not through
   global `BCF` after an await); identity-checked restoration on uninstall; lifecycle
   tests for hot disable/upgrade.
3. **`_activeSession` helper** — `Zotero.Integration.currentSession` is *not* cleared at
   command end (only `currentDoc`/`currentWindow` are — integration.js:346); new hooks
   must gate on `currentDoc`. Also fix the stale "cleared in its finally" key-fact in
   `CLAUDE.md` + `AGENTS.md` in this commit.
4. **Prewrite-failure fallback** — set `__bcfPrewriteActive` only when
   `_prepareCitationTexts` succeeds, so a prewrite bug doesn't silence the per-field path.
5. **Output-format gate fails closed** (`fmt !== "rtf"` required) with a loud diag; the
   same commit sets `outputFormat: "rtf"` on harness fixture sessions or the node tests
   break.
6. **Minor:** diag-gate the raw-field instrumentation; per-item CSL conversion cache in
   `session-run.js`; independent readiness retry for the Session patches.

## Decisions log

- **2026-07-27 — v2.0 is a long-lived feature branch**; no per-feature PRs; test builds
  share the `1.3.1.x` counter. Disk layout: `~/ClaudeCode/zotero` = main,
  `~/ClaudeCode/zotero-v2.0` = worktree on v2.0.
- **2026-07-27 — Foundation work lands on `v2.0`, not main.** No 1.3.2 hotfix release:
  the fixes have no reported user symptom, and the fail-closed gate change deserves the
  2.0 soak. If an urgent 1.3.x hotfix arises, cherry-pick the build.sh commit.
- **2026-07-27 — Style sync install contract (revised):** single fetch; explicit
  `Zotero.Styles.validate()`; `<id>` match required; install the validated bytes via
  `{string}`; await `Zotero.Integration.currentCommandPromise` before installing;
  generation token so shutdown prevents new installs. Two-tier failure contract
  (pre-install: untouched; install-stage: best-effort). Zotero itself propagates the
  update to open sessions via `resetSessionStyles()`.
- **2026-07-27 — Et-al override:** never delete `Zotero.Integration.sessions`;
  propagation = `clearEngineCache()` + `resetSessionStyles()` (sessions don't use the
  global engine cache — they never pass `cache` to `getCiteProc`). Strict fail-closed
  style gate on the global hook; scope to built-in styles initially; prefer a single
  `et-al-min` pref with `use-first=1`; applies in all output formats (it changes
  citeproc input, not RTF). Needs a real implementation plan before building.
- **2026-07-27 — Journal abbreviation:** identity fallback, never MEDLINE, for
  unrecognized keys under an allowed session; structured `{recognized, value}` engine
  contract. Type safety: prefer narrowing the Epps styles' non-journal `form="short"`
  call sites (needs its own render-diff verification), with session allow/deny sets as
  the fallback. Style precondition confirmed: `article-journal` branch uses
  `form="short"` (style line 615).

- **2026-07-27 — Model delegation.** Well-specified implementation chunks are delegated
  to **Opus subagents** working against the plan docs as specs (style-sync module +
  wiring + tests; et-al XML rewriter once its implementation plan exists; T6/T13 data
  entry and engine fixtures; doc-mirroring from written deltas). The main (Fable)
  session keeps: review of every delegated diff **before commit**, plan rewrites and
  design work, the Phase 4 provider patch, unspecified lifecycle/race semantics, the
  release chain, and final 2.0 verification. Delegated agents never commit.

- **2026-09-05 — Terminal periods are a Word macro, not a chain feature.** The integration API exposes no text around a field (`Field.INTERFACE` is ten methods; `Document.insertText` writes at the cursor), so "cite ends the footnote" is undecidable inside Zotero. A chain feature could only put the period *inside* the field; the user chose a plain-text period, which only Word can place. Bookmarks mode and LibreOffice unhandled.

## Blockers / open items

- **Journal abbreviation:** the pure abbreviation engine (T6/T13 word map, institutional
  rules) doesn't exist; licensing/edition decision (Indigo Book / CC0 basis) must be
  resolved before transcribing table content. Phase 0 spike (`engine.abbreviate()`)
  is the gate.
- **Et-al:** feasibility plan must be rewritten as an implementation plan (files,
  lifecycle, tests, DI seam for the XML rewriter — the node harness has no `DOMParser`).
- **Pending doc fix:** fold the review's resolved findings into
  `journal-abbreviation-render-time-feasibility.md` (CSL precondition now verified;
  identity fallback decided).
