## Task 1 — The subsequent et-al threshold may never exceed the first (Dan's decision)

**Rule (decided by Dan, 2026-10-31):** for every CSL scope, the effective
`et-al-subsequent-min` is never higher than the effective `et-al-min`.
Subsequent cites never list more authors than the first cite.

### Current problem
`BCF.etAl.rewriteXML` (lib/et-al-override.js) keeps the style's own subsequent
value when only the first threshold is overridden. The published Epps styles
have `<citation et-al-min="5" et-al-use-first="1" et-al-subsequent-min="4" ...>`.
If the user picks first = 3 and leaves subsequent on "Style default", the
result is first 3, subsequent 4. The subsequent cite is then longer than the
first, and native citeproc-js may also expand the first list (documented in
tests/README.md and Known limitations).

### Required behavior
For each scope, compute:

```
F = effective first min      = override `min`, else the style's inherited et-al-min
S = effective subsequent min = override `subsequentMin`, else the style's inherited
                               et-al-subsequent-min, else F (CSL default)
S_eff = min(S, F)
```

Write `et-al-subsequent-min = S_eff` whenever either override is active.
Write `et-al-subsequent-use-first`: `1` when an override sets or clamps it;
otherwise keep the inherited value.

Cases:
- first=3, sub=default → sub becomes 3 (clamped from the style's 4).
- first=default (5), sub=8 → sub becomes 5 (clamped to the style's first).
- first=6, sub=default (style 4) → sub stays 4.
- first=4, sub=7 → sub becomes 4.
- Both default → XML returned unchanged (as today).

**Inheritance must be correct per node.** CSL name options inherit
`style` → `citation`/`bibliography` → `names`/`name`. Today `originalMin`
falls back to the root `style` attributes, skipping the `citation` level.
Macros are shared between citation and bibliography, so a `name` inside a
macro inherits from whichever context calls it. Resolve it this way:
- Clamp at the root `style` and `citation` levels.
- For a `name`/`names` node that sets its own et-al attributes, compute F and S
  from its own attributes, falling back to the `citation` values (then
  `style`).
- Bibliography has no subsequent variant, so only the first override applies
  there, exactly as today.

Explain this resolution in a code comment.

### Settings pane
In `prefs-pane.js` `wireEtAl()` / `prefs.xhtml`:
- Disable (don't hide) subsequent-select options whose value is greater than
  the current effective first threshold. If the first threshold is "Style
  default", the effective first is 5 for the published styles. Read that from
  the installed main style's citation `et-al-min` if cheap; otherwise hardcode
  nothing and skip the disabling.
- If the stored `subsequentMin` exceeds the first threshold (old pref value, or
  first lowered later), leave the pref alone: the clamp is applied at render
  time. Show a short note under the selects: "Subsequent citations follow the
  first-citation setting when it is lower."
- Update the explanatory text in prefs.xhtml to state the rule.

### Tests (run-et-al-tests.js)
- Unit: every case listed above, plus a style with only `et-al-min` on
  `citation` (no subsequent attribute), a `name` node carrying its own
  `et-al-min`, and bibliography-only options.
- Rendering: replace the "subsequent above first → processor expansion"
  documentation with assertions. For every threshold combination across both
  built-ins, no subsequent rendering lists more names than the matching first
  rendering. Remove the corresponding caveat from tests/README.md and from the
  AGENTS.md Known limitations. The clamp makes it unreachable through the
  plugin.
- Pane: run-pane-tests.js covers option disabling and the note.

## Task 2 — Move the style-change command gate out of the et-al module

### Current problem
`BCF.styleSync` installs (startup main-style repair and the Settings "Install
style" button) go through `BCF.etAl.withStyleChange`. That gate only exists if
`BCF.etAl.install()` succeeded: it needs `commandRecord`, `resetRecord`,
`coordinator` and `live()`. If the et-al module fails to load or hook, the
no-opt-out self-repair of the main style fails with "Style-change command gate
unavailable". The repair exists precisely because the plugin is dead without
that style, so it must not depend on an optional feature.

### Required change
1. New file `lib/style-change-gate.js` exposing `BCF.styleGate` with:
   - `install(injected)`: installs the managed `Integration.execCommand` and
     `Integration.resetSessionStyles` wrappers through `BCF.patch._wrap`. It
     uses the same retry-until-available timer and the same lifetime rules as
     today.
   - `withStyleChange(task, current)`: today's semantics unchanged. That
     means: wait for running commands, hold new commands through the task,
     and settle every detached native reset, including after errors or
     cancellation.
   - `requestReset(clearFn)`: the coalescing reset job that et-al uses today.
     It takes a callback that clears engine caches before `resetSessionStyles()`.
   - `whenSettled()` and `uninstall(appShutdown)`: release the wrappers only
     after the queue and the resets settle.
2. The coordinator lives on `Zotero.Integration` as a non-enumerable,
   configurable property (`__bcfStyleGate`), not on `Zotero.Style.prototype`.
   The gate then needs no Style API. On install, if a legacy
   `Zotero.Style.prototype.__bcfEtAlCoordinator` exists (from a 1.3.3.x test
   build being hot-upgraded), adopt that object so that object stays shared,
   then move it. Keep the synchronous-adoption guarantee: the gate must arm
   before any `await`.
3. `lib/et-al-override.js` keeps only the XML transform, the `getCiteProc`
   wrapper, the pref observers and its cache handling. It calls
   `BCF.styleGate.requestReset(...)` for resets. Remove `withStyleChange`,
   the coordinator and the command/reset wrappers from it.
4. `lib/style-sync.js` `_defaultDeps().withStyleChange` calls
   `BCF.styleGate.withStyleChange`. It still fails closed if the gate is
   unavailable.
5. `bootstrap.js` changes:
   - Load order: `style-change-gate.js` after `patch.js` and before
     `style-sync.js` / `et-al-override.js`.
   - Startup: `BCF.patch.install()`, then `BCF.styleGate.install()`, then
     `BCF.etAl.install()`.
   - Shutdown: `styleSync.cancel()` → `dialog.uninstall()` →
     `await etAl.uninstall(appShutdown)` → `await styleGate.uninstall(appShutdown)`
     → `patch.uninstall()`.
   - Preserve today's teardown guarantee: the et-al disable reset still runs
     behind the command barrier, and the barrier is released only after it
     settles.

### Tests
- Move the gate cases from run-et-al-tests.js to a new `run-gate-tests.js`
  (add it to the npm `test` script and to tests/README.md). Keep every existing
  scenario: active command, command arriving mid-install, detached native reset,
  installer failure, hot upgrade, app shutdown, foreign wrappers.
- New: with `BCF.etAl.install` forced to throw (or the Style prototype
  missing), startup repair still installs the main style through the gate
  (run-style-setup-tests.js).
- New: hot upgrade from an instance whose coordinator lives on
  `Style.prototype.__bcfEtAlCoordinator` adopts it, and no command slips
  through during the upgrade.

## Task 3 — Stop re-reading and re-parsing the style on every engine request

### Current problem
With an override set, the `getCiteProc` wrapper does a synchronous file read
on every call (`Style.prototype.getXML` → `Zotero.File.getContents(independentFile)`),
then a DOM parse, a rewrite and a serialize. It does this even when native
`getCiteProc` is about to return a cached engine and ignore the rewritten XML.
`getCiteProc` is called on every session `setData`, and with `cache: true` from
Copy Citation, previews and Create Bibliography.

### Required change
- Memoize the rewritten XML in a `WeakMap` keyed by the `Zotero.Style`
  instance. Store `{ mode, xml }`, where `mode` is the existing
  `minimum + ":" + subsequent` string. On a hit with the same mode, install the
  cached string as the temporary `getXML` replacement without calling the
  original `getXML`. On a miss or a mode change, read, rewrite, store.
- Verify in `zotero11-style.js` that `Styles.init({reinit: true})`, called
  after every install, builds **new** `Zotero.Style` objects. If it does, the
  WeakMap key changes with each style revision and no staleness check is
  needed. If it doesn't, also key on the style's `<updated>` or file
  modification time, and say so in a comment.
- Keep everything else identical: the temporary-descriptor swap and restore,
  identity checks, failure delegation and the cache-mode `clearEngineCache`
  logic.

### Tests
- Repeated `getCiteProc` calls with an unchanged mode call the original
  `getXML` and the codec's parse only once per Style instance. A mode change
  re-reads. A new Style instance with the same ID re-reads.
- Rendering results unchanged.

## Task 4 — Small cleanups

1. **Double release at shutdown.** `patch.uninstall()` loops over every record
   in `BCF.patch._records`, including et-al/gate records their own uninstall
   already released. The second `_release` logs "changed by another patch;
   retired wrapper left inactive", which is false. Fix: `_release` sets
   `record.released = true` and returns early on a released record (or the
   owning module removes its records from `_records`). Add a wrapper-suite
   assertion that a normal shutdown logs no "changed by another patch" line.
2. **Silent override disable.** When `rewriteXML` throws "Unsupported CSL name
   options" (`et-al-use-last` / `disambiguate-add-names`), the override stops
   applying with only an Error Console entry. Record the last transform
   failure per style ID. Expose it through the pane bridge as a read-only
   `etAlStatus()`, and show one line under the et-al selects, e.g. "Override
   not applied to <style title>: unsupported name options in this style
   version". Keep the bridge minimal and remove it in teardown like the
   others.
